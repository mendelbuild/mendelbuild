Verification datastore

A non-production database Mendel may change and reset. Whether a Variation's migration only adds is settled by running it and comparing the structure before and after — reading the SQL is not enough — and doing that against production takes real locks on live tables. Mendel runs it here instead, then checks that the structure of the tables it touches matches production before it will admit anything.

Stored encrypted. Give it a database you would not mind losing: Mendel applies migrations to it and does not clean up after itself.

Why each of these

Gateway API
Nothing routes per Arm without it. Being on GKE does not imply it — Mendel's own cluster serves https and has none.
A production hostname
One gateway serves every deployment, and the hostname is what tells their traffic apart. No hostname means no route to match arms on.
https
A warning rather than a blocker. Over plain http the assignment cookie cannot be Secure, so it can be rewritten in transit and a visitor could choose their own arm.
A verification datastore
Only when a Variation changes the schema. Proving a migration additive means running it, and doing that against production takes real locks on live tables. An experiment that only changes what is shown needs none of this.
